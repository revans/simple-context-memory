# 1. Concept Name

Simple Context Memory

---

# 2. One-Sentence Description

A Claude Code plugin with three slash commands that give AI sessions structured, decision-focused memory — using a surgical shift handoff model so each session starts oriented, not cold.

---

# 3. Target Audience

Software engineers and technical founders who use Claude Code daily across multi-session projects and feel the compounding cost of lost context: re-explaining decisions already made, re-litigating settled questions, re-discovering root causes. Not beginners, not people who want a managed SaaS. People who write code with Claude and know exactly what it costs when a session starts cold.

---

# 4. Core Insight

The problem isn't that Claude forgets — it's that most memory systems save everything, which means Claude loads noise. A surgeon doesn't read the full patient chart on a shift handoff. They read a one-page note: what changed on this shift, what decisions were made and why, what's still open. Simple Context Memory implements that exact discipline. The structured format — seven named sections, each signaling what's load-bearing — does the compression work before the document enters context. Claude doesn't have to figure out what matters. The format already told it.

---

# 5. Page Sections (Ordered)

1. **Hero** — names the amnesia problem and the handoff solution. One command ends every session. One command starts the next.
2. **The Three Commands** — what `/opening`, `/closing`, and `/report` each do, at what time horizon, and what they produce. Positioned as a layered system, not three independent tools.
3. **The Anatomy of a Session Document** — walks through the seven sections of a `/closing` output. Highlights Roads Not Taken and Key Discoveries as the sections that never appear in code or git history.
4. **Roads Not Taken** — the concept deserves its own section. Shows a concrete example of a Do Not constraint with its reversal condition. This is the invisible guard rail that prevents future sessions from re-litigating settled questions.
5. **Compaction Protection Hooks** — the three-script layered defense. What each script does, when it fires, and how they cover each other's gaps.
6. **Why It Works** — the three-horizon model: session→note (`/closing`), note→context (`/opening`), history→current state (`/report`). Each command solves a different scale of the same problem.
7. **Installation** — one-command install with `init.sh`. Manual fallback. Global vs. project-level options.
8. **Get Started** — CTA to the GitHub repo (`https://github.com/revans/simple-context-memory`) and the one-command install.

# 9. Competitive Landscape

**Closest alternatives:**

- **CogniLayer** — persistent memory for Claude Code using a vector-DB recall model. Loads last session notes into context. Does not capture reasoning behind decisions, rejected alternatives, or Do Not constraints. It's a recall system; this is a decision archaeology system.

- **/handoff skill (AI Hero)** — compresses a single session into a markdown document for agent-to-agent transfer. Single-direction, no accumulation over time, no synthesis command, no compaction hooks. Solves handoff between agents in one session; doesn't solve continuity across a project's lifetime.

- **CLAUDE.md approach (built-in Claude Code)** — persistent instructions file for ongoing preferences. Not session-scoped. No structure for what was decided, why, or what was rejected. No mechanism for accumulating session history or synthesizing it at scale.

- **Raw context dumps** — the reflex solution: save everything to a memory file. No structure, no signal about what matters, high noise. Claude loads it and re-litigates anyway because it can't tell which of the forty facts is relevant now.

**White space:** Nothing implements structured decision archaeology with a three-command layered system covering session, context load, and historical synthesis. Every alternative saves *what happened*. Only this one saves *why it was done this way*, *what was explicitly rejected*, and *what a future session must not undo*.

# 10. Speculative Elements

- The claim that SBAR-C reasoning (used inside `/closing`) improves document quality is the intended design behavior, not a measured outcome. Frame as the reasoning framework the command uses, not a proven quality uplift.
- The `context-watch.py` script hardcodes `200_000` as the context window for `claude-sonnet-4-6`. This will be wrong for other models. The page should note this as a configurable constant, not a universal value.
- No speculative headline claims detected in the README. All core behavioral claims (the commands write files, `/report` is incremental, hooks fire on compaction events) are based on demonstrated Claude Code behavior and shipped code.
